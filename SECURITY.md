# Безопасность

## Как сообщить об уязвимости

Не пишите об уязвимости в открытом issue. Используйте закрытое сообщение GitHub:

1. Откройте вкладку **Security** этого репо
2. Нажмите **Report a vulnerability**

Прямая ссылка: https://github.com/openpalliative/pal-directory/security/advisories/new

Сообщение увидят только мейнтейнеры. Отдельной почты для этого нет. Если уязвимость касается другого репо openpalliative, сообщите в нём, путь тот же

Опишите, что нужно сделать, чтобы повторить проблему, и что вы ожидали. Не прикладывайте настоящие личные данные, достаточно выдуманных

Проект ведут добровольцы, дежурства нет. Мы постараемся ответить в течение 14 дней и сообщим, когда выйдет исправление. Если хотите, укажем вас в благодарностях, под именем или псевдонимом

## Что считаем уязвимостью

- выполнение чужого кода на странице (XSS) через поиск региона, адрес страницы (`#region=`, `#back=`) или запомненный регион в браузере
- любой запрос с сайта за пределы своего адреса: сайт читает только свои файлы
- ссылка «Сообщить об ошибке» уносит в issue больше, чем код региона, код строки и версию данных
- подмена данных в релизе: zip в релизе должны совпадать с `SHA256SUMS`
- небезопасные GitHub Actions: инъекции в шаблоны, лишние права токена, непиннованные экшены, обход проверки PR наблюдателя
- наблюдатель (`pipeline.watch`) ходит на адрес вне списка из README, раздел «Источники и санкционные рамки»

Неверный номер, устаревшая подпись или часы работы это не уязвимость. О них пишите в issue по форме «Неверный номер»

## Как устроена защита

- Сайт статический, сервера с данными людей нет. Регион, если вы попросили его запомнить, хранится только в вашем браузере, кнопка «забыть» его стирает
- Аналитики, счётчиков, cookie и внешних шрифтов нет. Тесты проверяют, что страницы не делают запросов за пределы своего адреса
- Content-Security-Policy задана через `<meta http-equiv>` в `<head>` раньше любых скриптов и стилей. GitHub Pages не даёт задать свои HTTP-заголовки, поэтому `frame-ancestors`, `report-uri` и `sandbox` так задать нельзя: через meta браузер их не применяет. Встраивание сайта в чужой фрейм этим способом не запретить
- Нет инлайн-скриптов, обработчиков `on*=` в разметке и атрибутов `style`, это проверяет `opsite check`
- Наблюдатель ходит в сеть только по списку хостов в коде, тест это проверяет. Новые данные он присылает PR, а не правит `main`, кроме служебного снимка с датой проверки
- Экшены в workflows закреплены по SHA, у токена минимальные права, кэш выключен там, где собирается то, что публикуется

## Поддерживаемые версии

Исправления выходят только для последней версии на GitHub Pages и в ветке `main`. Если вы развернули копию у себя, обновите её из последнего релиза

## English

Please report vulnerabilities privately via GitHub private vulnerability reporting (Security tab, Report a vulnerability). Do not open a public issue. The site is static, makes no external requests and keeps the remembered region only in your browser
